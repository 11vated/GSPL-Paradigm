### 4B. SEMANTIC PARSER PIPELINE

The parser must convert ANY natural language input into structured concept data:

1. **Tokenization** — Break input into words, handle compound concepts ("ice dragon" is one concept)
2. **Trie-Based Concept Detection** — O(n) matching against all 6 taxonomy tries simultaneously
3. **Context Resolution** — Disambiguate: "light armor" (weight) vs "light element" (holy/radiant). Use surrounding tokens for context.
4. **Relationship Extraction** — Identify modifiers: "fire dragon" = dragon species + fire element overlay. "Dark elf archer" = elf species + shadow element + archer archetype.
5. **Implicit Inference** — Unstated but implied: "ninja" implies rogue archetype + humanoid + stealth abilities + dark clothing + agility. "Angel" implies winged humanoid + light element + healer or warrior archetype + white/gold color.
6. **Confidence Scoring** — Weight matches by specificity and context. "Dragon" is 99% species confidence. "Fiery personality" is 10% fire element confidence (metaphorical, not literal).
7. **Unknown Concept Handling** — If a concept doesn't match any taxonomy, classify as novel and infer properties from closest neighbors. "Zorblax" → unknown species → analyze phonetics (aggressive consonants = predator?) → request user clarification or generate best-guess.

Takes parsed concepts and composes them into a unified ConceptGraph:

- **Conflict Detection**: chibi + photorealistic = incompatible styles → suggest resolution or hybrid
- **Emergent Property Discovery**: dragon + ice + undead = "Frostlich Wyrm" with: frost breath (ice+dragon), necrotic aura (undead), skeletal wings (undead body), ice crystal bones (ice+bone material)
- **Inheritance Application**: dragon inherits winged body + fire breath defaults → ice element overrides fire to frost, retains flight
- **Property Merging**: Multiple archetypes merge personality vectors (warrior + healer = paladin tendencies)
- **Constraint Propagation**: style choice constrains proportions (chibi = 1:2 ratio, realistic = 1:7.5)

### 4D. CONSTRAINT SATISFACTION SOLVER

Iterative relaxation over rules ensuring quality:

- **Proportion Constraints**: Head-to-body ratio must match style. Limbs must be anatomically possible for movement type.
- **Silhouette Readability**: Entity must be recognizable as a silhouette at 64x64 pixels.
- **Style Consistency**: All visual elements must belong to the same style taxonomy leaf.
- **Anatomical Validity**: Body structure must support declared movement capabilities (can't fly without wings or magic/levitation ability).
- **Animation Feasibility**: Declared abilities must have feasible animation paths given skeleton structure.
- **Power Balance**: Abilities must have proportional limitations (no cost-free infinite power).

### 4E. KNOWLEDGE ACCUMULATOR

- Every entity created enriches the ontology
- New concept combinations stored as "recipes" (fire + undead + dragon = "Frostlich Wyrm" recipe)
- Popular patterns promoted to first-class concepts
- Constraint violations create new rules
- The system gets smarter over time WITHOUT external AI

## SECTION 5: UNIVERSAL TRANSFORMATION SYSTEM

Transformations are core to anime, comics, games — any entity can have transformation chains.

### Transformation Classification:

**Power-Up Chains** (vertical escalation — each form strictly stronger):
Example: SSJ1 → SSJ2 → SSJ3 → SSJ God → SSJ Blue → Ultra Instinct
Model: Linear chain of stages, each multiplying base power, each with visual + ability changes.

**Mode Switches** (lateral — different ability set, not strictly stronger):
Example: Naruto's Sage Mode vs Bijuu Mode vs Baryon Mode
Model: Parallel power branches, each accessing different energy source.

**Weapon/Spirit Releases** (staged manifestation of bonded entity):
Example: Bleach Zanpakutō — Sealed → Shikai → Bankai
Model: Progressive unlocking of a companion entity's power.

**Awakenings** (dormant potential triggered by extreme circumstance):
Example: Devil Fruit Awakening, Nen Awakening
Model: Binary flip — unawakened vs awakened — with dramatic capability expansion.

**Fusions** (two+ entities merge into composite being):
Example: Dragon Ball Fusion Dance, Steven Universe Gem Fusion
Model: Input entities + compatibility score → output entity with merged traits + new personality.

**Equipment Transformations** (external source of power):
Example: Iron Man suit-up, Power Rangers morph, Magical Girl transformation
Model: Item activation → visual sequence → equipped state with new abilities.

**Emotional Triggers** (involuntary activation from emotional threshold):
Example: Super Saiyan first triggered by rage, Berserk armor
Model: Emotion exceeds threshold → automatic transformation → potential loss of control.

## SECTION 6: ADVANCED ANIMATION ENGINE

### Disney's 12 Principles — Applied to EVERY Style:

1. **Squash & Stretch** — chibi: extreme (100%). Realistic: subtle (10%). Cartoon: maximum (150%).
2. **Anticipation** — wind-up before every action. Duration scales with style.
3. **Staging** — silhouette readability at every frame. Camera angle serves clarity.
4. **Straight Ahead / Pose to Pose** — hybrid: key poses for precision, interpolation for flow.
5. **Follow-Through / Overlapping Action** — hair, capes, tails, chains, energy trails continue after body stops.
6. **Ease In / Ease Out** — cubic bezier curves on all motion. Sharp for impacts, smooth for grace.
7. **Arcs** — all natural motion follows curved paths. Only mechanical entities use linear.
8. **Secondary Action** — breathing, blinking, weight shifts during primary actions.
9. **Timing** — personality expressed through frame spacing. Confident = measured. Nervous = irregular.
10. **Exaggeration** — style-dependent scaling. Chibi: 200%. Anime: 150%. Realistic: 105%.
11. **Solid Drawing** — 3D volume maintained through all poses, even in 2D.
12. **Appeal** — every entity must have visual magnetism appropriate to its role.

### Anime-Specific Techniques:

- **Speed Lines**: Radiating directional lines indicating velocity and direction of motion
- **Impact Frames**: Freeze-frame on hit moment. Hold duration = perceived impact intensity. Often with inverted colors or flash.
- **Smear Frames**: Single distorted frame bridging fast motion. Shape stretches into blur between key poses.
- **Limited Animation with Dynamic Cuts**: Animate on 3's (8fps effective) for dialogue, on 1's (24fps) for action peaks. Camera cuts create energy without frame count.
- **Sakuga Bursts**: Key animator solo sequences where frame count and quality spike dramatically for emotional/action climax.
- **Power-Up Sequences**: Extended transformation animations with layered VFX, camera orbits, environmental reaction.
- **Screen Flash / Invert**: Brief white or inverted-color frame on maximum impact.
- **Background Blur / Zoom Lines**: Background streaks during motion to emphasize speed.

### Cartoon Physics Engine:
- **Gravity Delay**: Character runs off cliff → holds position → looks down → THEN falls
- **Hammerspace**: Items pulled from nowhere (inventory that defies physics)
- **Toon Force Scaling**: Funnier outcome overrides physical laws
- **Elastic Recovery**: Crushed → flat → pops back to normal shape
- **Body Part Independence**: Eyes pop out, jaw drops to floor, heart beats visibly through chest
- **Rule**: If the animation would be funnier or more expressive breaking physics, break physics.

### Procedural Animation Systems:
- **Walk Cycle Generator**: Input personality → output unique walk (confident stride, nervous shuffle, swagger, stealth)
- **Idle Animation**: Breathing, weight shifts, looking around, fidgets — personality-driven
- **Combat Animation**: Attack chains, dodge rolls, blocks, hit reactions — archetype-driven
- **Emotional Animation**: Joy bouncing, sadness slumping, anger trembling, fear shrinking

### VFX Layer System:
```
VFX Stack (rendered bottom to top):
├── Layer 0: Environment Reaction (ground cracks, water ripples, wind in grass)
├── Layer 1: Aura (base energy field around entity — color = element)
├── Layer 2: Particle Emitters (sparks, dust, embers, snowflakes)
├── Layer 3: Ability Visuals (beams, projectiles, constructs, domains)
├── Layer 4: Screen Effects (shake, flash, chromatic aberration, motion blur)
└── Layer 5: Cinematic (slow motion, camera zoom, depth of field)
```

### Cinematic Camera System:
- **Normal Gameplay**: Fixed or following camera, standard framing
- **Ability Activation**: Camera pulls back for wind-up, then zooms in on release
- **Transformation**: Camera orbits entity during transformation, dramatic low angle
- **Special Move**: Camera cuts to dramatic angle, slow motion on impact, speed-up on follow-through
- **Emotional Moment**: Close-up on face, depth of field blurs background, slow push-in

## SECTION 7: SDF-BASED GENERATION ENGINE

### Why SDF (Signed Distance Fields):

- **Resolution independent** — infinite zoom, any output size from 16px to 8K
- **Boolean operations** — union/subtract/intersect shapes naturally
- **Smooth blending** — soft merging between body parts
- **Analytical normals** — perfect lighting without normal maps
- **Natural LOD** — scale computation cost to output need
- **GPU-acceleratable** — shaders evaluate SDFs at real-time rates
- **Style-agnostic** — same mathematical foundation renders pixel art AND photorealism

### SDF Primitive Library:
```
SDF Primitives:
├── Sphere (head, joints, eyes, orbs)
├── Capsule (limbs, torso, tails, fingers)
├── Box (mechanical parts, armor plates, buildings)
├── Torus (rings, halos, circular features)
├── Cylinder (columns, tubes, barrels)
├── Cone (horns, spikes, pointed features)
├── Ellipsoid (egg shapes, body variations)
└── Custom (bezier-defined curves for unique shapes)

SDF Operations:
├── Union (combine shapes)
├── Subtraction (carve from shapes)
├── Intersection (keep only overlap)
├── Smooth Union (organic blending between shapes, controlled radius)
├── Smooth Subtraction (organic carving)
├── Round (add radius to sharp edges)
├── Shell (hollow out shapes)
├── Twist (spiral deformation)
├── Bend (arc deformation)
├── Elongate (stretch along axis)
└── Repetition (tile/mirror shapes)
```

### Generation Pipeline:
1. **Skeleton Definition** → map body structure to joint hierarchy
2. **SDF Primitive Assignment** → each body part gets primitives (head = sphere, arm = capsule)
3. **Smooth Union Assembly** → blend connected parts with style-appropriate radius
4. **Detail Carving** → subtract/intersect for features (eye sockets, mouth, armor details)
5. **Style Post-Processing** → outline extraction (anime), pixel snapping (pixel art), subsurface scattering (realism)
6. **Material Application** → SDF-space texturing based on material taxonomy
7. **Rasterization** → render at target resolution for target medium

### Realism Pipeline (when style = photorealistic):
- Subsurface scattering for skin (light penetrates surface, scatters, exits)
- Physically-based rendering (PBR) materials with metallic/roughness maps
- Global illumination via SDF cone tracing (ambient light bouncing)
- Screen-space ambient occlusion (darkening in crevices)
- Depth of field, motion blur, chromatic aberration
- Micro-detail: pores, wrinkles, fabric weave, hair strands (thousands)
- Muscle deformation under skin during animation
- Cloth simulation with collision response
- Hair simulation with wind/gravity/collision

## SECTION 9: THE SEED — GST 4.0 SPECIFICATION

The seed is the atomic unit of GSPL. EVERYTHING is a seed. A character is a seed. A world is a seed containing seeds. An ability is a seed attached to an entity seed. A style is a seed that modifies rendering.

### 9 Gene Types:
```typescript
type GeneType = 'scalar' | 'categorical' | 'vector' | 'expression' | 'struct' | 'array' | 'graph' | 'tensor' | 'timeseries';

// Categorical: one-of-N (archetype: "warrior" | "mage" | ...)
```
